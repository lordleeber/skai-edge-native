# Orin Nano baseline — 2026-09-26

Local Release run, using the real TensorRT engine and Console UI in Firefox 147.
The controlled RTSP source is 1280×720 at 30 FPS. HTTP and the browser are on the
same Jetson; ICE uses configured host candidates. This is an instrumented local
baseline with a synthetic scene. It does not measure remote camera sensor/ISP,
external LAN travel or another device's rendering performance.

Environment: Orin Nano Super reference developer kit, L4T R36.4.7,
Linux 5.15.148-tegra, 25W mode, schedutil, CPU0 observed at 1190.4–1344 MHz and GPU at
306 MHz. Build: `BUILD_TESTING=OFF`, TensorRT ON, Release (`-O3 -DNDEBUG` for C++
and CUDA). Exact compiler, engine/binary/tool/UI hashes and parameters are in
[the compact JSON](orin-nano-2026-09-26.json).

Warmup: 10 s; observed: 60.80 s, 59 intervals.

Stage/queue/receiver p95 values describe interval averages; source-to-browser p95
uses individually checked timestamp samples. Stage means use weighted cumulative
deltas; CPU/GPU/RSS/FPS means describe samples. Server annotation has no samples
and native encode CPU is not applicable to the H.264 passthrough graph. The
browser annotation value measures canvas draw submission, not GPU completion.

The window includes 1824 delivered source frames, 1824
inference commits and 323 checked latency samples. Inference rate was
30.002 FPS. The observer saw 26.614 video-frame callbacks/s;
that is an observed callback rate, not a guarantee of compositor FPS. The maximum
observed browser wall/monotonic-origin discrepancy was 1.0 ms.

Queue drops during collection: inference 0, encoded recording
0, WHEP 0. The peer reported 0.115 Mbit/s sent.
Both finalized MP4s decoded to EOS (2284 total frames). SQLite integrity
passed after shutdown; all owned processes exited cleanly.

The complete local evidence is `build/profile-release-baseline-20260926/report.json`,
with its SHA-256 recorded in the compact JSON. The collector ran before its feature
branch commit; the recorded parent revision/dirty flag and matching artifact
hashes describe that working tree. Native runtime, collector and UI changes are
reviewable in the two Step 38 PRs.

For reproducibility and measurement limits, see the
[profiling guide](../step38-profiling-baseline.md). These are local/operator results,
not independently verified CI results.
